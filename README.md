# Mood

Соцсеть о книгах: фрагмент книги и мнение читателя хранятся и показываются отдельно. Открытая лента доступна без аккаунта. Лайки, комментарии, подписки, сохранение, отправка ссылки, открытие профиля и создание публикации требуют входа.

## Запуск

Для запуска мышью откройте **Mood** на рабочем столе или `Mood.desktop` в папке проекта. Ярлык запускает PostgreSQL и сервер, проверяет готовность базы и открывает сайт в браузере. Повторное нажатие открывает уже работающий сайт. Если запуск завершится ошибкой, окно останется открытым с причиной.

```bash
cd /home/yernur/Mood
./run
```

Открыть **http://localhost:8088**. Нужны Go ≥ 1.25, Node.js ≥ 22.12 и PostgreSQL с `initdb`/`pg_ctl` либо Docker Compose. `./run` создаёт `.env` со случайным паролем, отдельный кластер PostgreSQL на `127.0.0.1:5438`, базу и таблицы; собирает фронтенд и backend. Системные базы не изменяются. Для запуска в терминале с журналом используйте `./run --foreground`.

```bash
./stop
```

Остановка сохраняет данные. При Docker-варианте базу можно остановить через `docker compose stop db`.

Данные: `.data/postgres/`, `.data/uploads/`. Журналы: `.data/server.log`, `.data/postgres.log`. Не публикуйте `.env` и `.data` — они исключены из Git.

Если используется существующая БД, укажите `DATABASE_URL` в `.env` и запустите `MOOD_EXTERNAL_DB=1 ./run`. Пользователю БД нужны права создания таблиц и индексов в выбранной схеме.

Подбор книг по эмоции требует доступного LLM-провайдера (OpenAI-совместимое API; по умолчанию `https://llm.alem.ai/chat/completions` и модель `gpt-oss`). Адрес, ключ и модель задаются в `.env` переменными `LLM_API_URL`, `LLM_API_KEY` и `LLM_MODEL`. Без рабочего провайдера весь остальной сайт работает, а блок подбора показывает «временно недоступен».

### Полный запуск в Docker

```bash
cp .env.example .env
# Заменить пароль в .env (и в DATABASE_URL для локального запуска).
docker compose --profile container up --build -d
```

Приложение доступно по тому же адресу; база и загрузки сохраняются в именованных томах. Не запускайте одновременно контейнерное и локальное приложение на одном порту.

## Что работает

- Открытая лента с постраничной загрузкой; отдельная лента авторов, на которых вы подписаны.
- Регистрация: никнейм, фамилия и имя, обязательное фото JPG/PNG, адрес Gmail, пароль от 10 символов. Вход и выход; сессия сохраняется после обновления страницы.
- Два типа публикаций: цитата с собственным мнением, страницей и строками; рекомендация книги.
- Лайки, комментарии с пагинацией, сохранение, отправка ссылки на отдельный пост.
- Публичная библиотека с поиском; карточка книги, автор, описание, благодарность загрузившему. Можно добавить только карточку либо приложить файл книги (PDF, EPUB, FB2, TXT или DOCX) размером до 100 МБ. PDF сохраняется целиком и читается в ридере; остальные форматы сервер разбирает в текст: страницы попадают в `book_pages`, и книгу любой читатель открывает в текстовом режиме ридера.
- Подбор книг по эмоции в три шага. Читатель пишет, что чувствует; сначала код быстро ищет совпадения слов эмоции в названиях, авторах, жанрах и описаниях библиотеки (без LLM). Затем один вызов LLM (OpenAI-совместимое API, по умолчанию `gpt-oss` на `llm.alem.ai`) получает каталог книг и подсказку код-поиска и выбирает ровно 3 книги с объяснением, почему каждая откликается на эмоцию. Дальше цитаты ищутся параллельно — по одному вызову LLM на книгу: сервер показывает модели релевантные страницы «тела» книги (титулы и оглавления отбрасываются; для PDF текст извлекается из файла и кэшируется в `book_pages`), а она берёт 1–3 предложения, откликающиеся на эмоцию. Цитата валидируется дословно по тексту книги (`findExcerptPage`); если модель не подтверждается, сервер подставляет безопасный отрывок из «тела» книги. Выбор валидируется на сервере: ровно 3 уникальных существующих книги. Результат идёт потоком (SSE): резюме, затем каждая книга сразу, как готова её цитата; JSON-эндпоинт `/api/mood` отдаёт то же самое целиком. В интерфейсе у каждой книги — обложка и реальная страница с отрывком; клик по карточке открывает страницу крупно с кнопкой «Читать книгу», и ридер стартует именно с этой страницы. Если провайдер недоступен или ответ модели не распознан, срабатывает детерминированный подбор (3 книги с полным текстом, по числу «спасибо»), поэтому подбор всегда возвращает результат. Работает без входа, лимит 5 запросов/мин с IP.
- Проверка повторной загрузки: уникальное нормализованное сочетание названия и автора; отдельно SHA-256 содержимого файла. Ограничения БД защищают от одновременных дубликатов. Разные издания пока считаются одной книгой.
- Профили читателей, подписка/отписка, счётчики, собственные публикации.
- Поиск по названию книги, автору, цитате и мнению; адаптивная раскладка, мобильная навигация, диалоги с управлением клавиатурой.
- Шрифты, иконки и обложки работают локально; сторонние CDN для отображения не нужны.

Первый запуск добавляет три демонстрационных профиля и публикации. Это примеры интерфейса; страницы и строки в них условные, полные файлы книг не приложены. У демонстрационных профилей отключён вход. Для пустой установки задайте `SEED_DATA=false` до первого запуска.

## Устройство проекта

```text
backend/
  main.go          HTTP-сервер, маршруты, аутентификация и защита запросов
  content.go       Публикации, комментарии, библиотека, профили, файлы
  mood.go          Подбор книг по эмоции: код-предфильтр, LLM-выбор 3 книг, цитаты и валидация
  schema.sql       Таблицы, ограничения и индексы (встроены в Go-бинарник)
  main_test.go     Модульные и интеграционные тесты с отдельной схемой БД
frontend/src/
  App.tsx          Навигация, состояние экранов и загрузка данных
  api.ts           Типизированные обращения к API
  types.ts         Модели данных
  components/      Auth, Composer, AddBook, PostCard, MoodPicker, общие UI-компоненты
  styles.css       Палитра, типографика и адаптивная сетка
frontend/public/   Локальные шрифты и значок
run / stop        Запуск и остановка
compose.yml       PostgreSQL и необязательный контейнер приложения
Dockerfile        Сборка React + Go
 tests/           Браузерные сценарии и снимки для визуальной проверки
```

Go использует стандартный `net/http`, драйвер `pgx` и пул до 10 соединений. PostgreSQL: внешние ключи, уникальные индексы, индексы ленты, профилей, связей, комментариев. Ответы ограничены: 20 постов, 30 книг или 50 комментариев. Пагинация по ID. Поиск подстрокой подходит для первой версии; полнотекстовый поиск/триграммы и нагрузочное тестирование нужны при росте каталога.

React + TypeScript + Vite; готовые доступные диалоги Radix UI и иконки Lucide. Компоненты разделены по назначению; TypeScript работает в строгом режиме. Для форматирования: `cd frontend && npm run format`.

## Защита данных

Пароли хешируются Argon2id (19 МиБ, 2 прохода, случайная соль); исходные пароли не сохраняются. Сессии — случайные 256-битные токены, в БД только SHA-256, в браузере `HttpOnly` + `SameSite=Lax` cookie, срок 30 дней; выход отзывает сессию. Токенов в localStorage нет.

API проверяет права на сервере, использует параметры SQL, проверку Origin/Fetch Metadata для изменений, ограничения частоты и размера запросов, таймауты, CSP и заголовки защиты. Хеширование ограничено четырьмя параллельными операциями. Фото декодируются и заново кодируются в PNG; исходные метаданные удаляются. Личные email и хеши не возвращаются в публичных профилях.

Это работающая локальная первая версия. Gmail пока проверяется по формату, без письма подтверждения; OAuth Google, восстановление пароля, модерация и жалобы ещё не реализованы. Проверка PDF по сигнатуре и размеру не является антивирусной проверкой. Для публичного размещения необходим HTTPS (`APP_ORIGIN=https://...`, `COOKIE_SECURE=true`), резервное копирование БД и файлов, а также TLS к удалённой базе. Rate limit сейчас хранится в памяти одного экземпляра. Полной гарантии от взлома не существует.

Рекомендации по хранению паролей и сессий: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html), [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Документация пула: [pgxpool](https://pkg.go.dev/github.com/jackc/pgx/v5/pgxpool).

## Полная библиотека, чтение и демо-наполнение

В локальную базу добавлены 8 полных PDF-изданий, 48 новых демонстрационных профилей, 48 публикаций, 192 комментария и 1027 демонстрационных лайков. Первоначальные три учебных профиля тоже помечены как демо. У всех таких профилей отключён вход; их email используют зарезервированный домен `.invalid`. Реальные аккаунты не изменяются.

Книги: «Хамелеон», «Чем люди живы», «Сон смешного человека», «Шинель», «Искусство войны», «Наедине с собой», «История свечи», «Автобиография» Франклина. Первые четыре — на русском, остальные — на английском. Язык, тема, количество страниц и источник показаны в карточке. Для «Истории свечи» подготовлено полное текстовое издание без иллюстраций; оригинальная страница доступна по ссылке источника.

Тексты скачаны из Викитеки и Project Gutenberg, пересказы вместо книг не используются. Источники записаны в [sources.json](data/catalog/sources.json). Каждая цитата дословно проверена по скачанному тексту. Страницы и строки относятся к PDF-изданию Mood: строки считаются в теле текста без заголовка, номера страницы и пустых межабзацных интервалов. Мнения и обсуждения — редакционно написанные примеры, а не отзывы реальных читателей. Пол и манера речи демо-профилей согласованы с их репликами.

В карточке файла есть кнопка «Читать книгу». Читалка на React-PDF/PDF.js загружается отдельным модулем по требованию, отображает только текущую страницу и не содержит инструментов выделения или аннотирования. Есть переход к странице, масштаб, скачивание и запоминание позиции в браузере. Полный PDF доступен через `GET /api/books/{id}/read`; поддерживаются диапазоны байтов. Чтение доступно гостям.
Книги из EPUB/FB2/TXT/DOCX отображаются текстом: сервер делит текст на страницы по ~1500 символов, ридер показывает их через `GET /api/books/{id}/pages?from=&to=` (до 10 страниц за запрос).

Темы фильтруются через `GET /api/posts?topic=Наука`. Список читателей для настольной панели — `GET /api/readers`. На широких экранах используются три колонки, на ноутбуках меньшей ширины боковая панель скрывается, на телефонах остаётся нижняя навигация.

Воспроизводимый импорт (после запуска PostgreSQL):

```bash
python3 -m venv .data/books-venv
.data/books-venv/bin/pip install -r tools/requirements-books.txt
.data/books-venv/bin/python tools/download_books.py
.data/books-venv/bin/python tools/build_book_pdfs.py
.data/books-venv/bin/python tools/prepare_discussions.py
set -a
source .env
set +a
.data/books-venv/bin/python tools/import_demo.py
```

Исходные тексты, PDF и карта страниц хранятся в `.data/catalog/`, файлы библиотеки — в `.data/uploads/`. Импорт обновляет только свои записи по стабильным ключам; повторный запуск не создаёт дубликаты. Рекомендации и мнения находятся в `data/catalog/`. Для новой проверки читалки и адаптивности: `node tests/library-reader.mjs`; загрузки книг файлом (TXT/FB2 через UI, чтение гостем): `node tests/upload-book.mjs`.

## Обложки и страницы публикаций

У 13 книг установлены фотографии/изображения обложек реальных изданий. Перечень изданий, исходные изображения и ссылки на издателей или каталоги находятся в `data/catalog/covers.json`. В БД сохраняются `cover_path`, `cover_source` и `cover_edition`; изображения обслуживаются локально из `.data/uploads/`. В карточке книги есть ссылка на выбранное издание обложки. Обложка не означает, что подготовленный PDF воспроизводит полиграфию или перевод именно этого печатного издания; текст и его источник указаны отдельно.

Для повторного импорта обложек, с переменными из `.env`: `.data/books-venv/bin/python tools/import_covers.py`. Импорт не меняет PDF, страницы или цитаты.

Нажатие на текст/свободное место поста, его дату или кнопку комментариев открывает `/?post=ID`. Публикация показывается целиком, комментарии находятся под ней. Чтение обсуждения доступно гостю, отправка ответа требует входа. Работают прямая ссылка, обновление страницы, браузерные переходы назад/вперёд и возврат к прежней позиции ленты. Кнопки книги, профиля, лайка и сохранения выполняют свои действия без перехода в пост.

Браузерная проверка: `node tests/post-detail.mjs`. Она проверяет файлы обложек, страницу публикации, расположение комментариев, гостевой доступ, вход для ответа, историю переходов, мобильную библиотеку и чтение PDF.

В библиотеке есть фильтр «Жанр»: он применяется на сервере вместе с поиском и курсорной пагинацией. Список жанров берётся из каталога через `GET /api/books/genres`. При добавлении книги жанр передаётся полем `genre` multipart-формы; если поле отсутствует, используется «Классика». Проверка интерфейса: `node tests/book-genres.mjs`.

## Сохранённые книги

В разделе «Сохранённое» две вкладки: «Публикации» и «Книги». Закладка доступна рядом с книгой в каталоге и в её карточке. Из сохранённой книги можно открыть PDF. Сохранения привязаны к аккаунту, не к локальному хранилищу браузера.

API: `PUT /api/books/{id}/save`, `DELETE /api/books/{id}/save`, `GET /api/books?feed=saved`. Действия требуют входа; повторное сохранение или удаление идемпотентно. Поле `saved` в ответах книг относится только к текущему пользователю. Публичный каталог не раскрывает чужие закладки. Таблица `book_saves` имеет составной первичный ключ и каскадное удаление связей; сохранённые публикации остаются в отдельной таблице.

Проверка интерфейса с очисткой тестового аккаунта (с переменными из `.env`): `MOOD_TEST_CLEANUP=1 node tests/saved-books.mjs`. Go-тесты дополнительно проверяют разграничение аккаунтов, идемпотентность, фильтры, пагинацию, вход/выход и независимость книжных закладок от публикаций.

## Разработка

Backend (из корня проекта, после запуска БД):

```bash
set -a
source .env
set +a
export APP_ORIGIN=http://localhost:5178
cd backend
go run .
```

В другом терминале: `cd frontend && npm run dev`. Vite проксирует `/api` и `/uploads` на Go-сервер. Для изменения сервера 8088 сначала остановите ранее запущенный экземпляр приложения. Для сборки: `cd frontend && npm run build`, `cd backend && go build .`.

## Проверки

```bash
# Быстрые модульные проверки; без TEST_DATABASE_URL интеграционный тест пропускается.
cd backend
go test -race ./...
go vet ./...
```

Из корня проекта для проверки на PostgreSQL:

```bash
set -a
source .env
set +a
(cd backend && TEST_DATABASE_URL="$DATABASE_URL" go test -race -v ./...)
```

Интеграционный тест создаёт отдельную случайную схему и удаляет её после завершения: проверяет регистрацию, хеширование, cookie, гостевые ограничения, PDF, оба вида дубликатов, разделение цитаты и мнения, лайки, комментарии, сохранение, подписки, CSRF, вход и отзыв сессии.

Браузерная проверка работающего приложения:

```bash
# При необходимости: cd frontend && npx playwright install chromium
# Из корня проекта, с переменными из .env:
MOOD_TEST_CLEANUP=1 node tests/flows.mjs
node tests/preview.mjs
```

Можно задать `CHROMIUM_PATH` и `MOOD_URL`. Браузерный сценарий проверяет полный путь читателя и удаляет созданные им данные, когда включён `MOOD_TEST_CLEANUP=1` и доступна БД. Снимки сохраняются в `tests/artifacts/`.

## Основные маршруты API

| Маршрут | Назначение |
| --- | --- |
| `GET /api/health` | Готовность PostgreSQL |
| `POST /api/auth/register`, `/login`, `/logout` | Регистрация, вход, выход |
| `GET /api/me` | Текущий пользователь или `null` |
| `GET /api/posts?feed=following\|saved&before=ID&q=...&user=ID&book=ID` | Лента, фильтры и пагинация |
| `GET /api/posts/{id}` | Отдельный пост |
| `POST /api/posts` | Создание публикации |
| `PUT/DELETE /api/posts/{id}/like`, `/save` | Лайк и закладка, идемпотентно |
| `GET/POST /api/posts/{id}/comments` | Комментарии, `?after=ID` для пагинации |
| `GET /api/books?q=...&genre=...&before=ID`, `/api/books/{id}` | Каталог и книга |
| `POST /api/books` | Книга: multipart `title`, `author`, `description`, `file` |
| `PUT/DELETE /api/books/{id}/like` | Благодарность загрузившему |
| `GET /api/users/{username}` | Профиль и счётчики |
| `POST /api/mood` | Подбор 3 книг по эмоции (LLM) |
| `GET /api/mood/status` | Доступность модели подбора и её имя |
| `PUT/DELETE /api/users/{id}/follow` | Подписка |

Шрифты Manrope и Literata распространяются по SIL Open Font License; лицензии находятся в `frontend/public/fonts/`.
